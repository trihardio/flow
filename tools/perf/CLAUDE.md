# tools/perf: the journeys

What `tools/perf` is, and the rule not to run a journey while he may be trying the app himself, are in the project's `CLAUDE.md`. This file was part of it until 13 October 2026; it is here so that it is only read when this folder is worked in.

- `npx vite build --outDir "$TMPDIR/flow-perf/dist"`, then `env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron tools/perf/run.cjs finance --trace` (also `trade`, `stocks`, `launch`, `flow`: stills of the side titles, the Left over tab, the score pop-up and the insights, run with `--shots`; `cards`: the finance month scrolled down card by card, then Money flow folded and opened twice, and `pull`: a card out of its wallet and back, turned round half-way, another wallet pressed meanwhile, then the coin on the trading panel under the pointer), then `node tools/perf/report.cjs finance` (`--programs` lists the graphics programs).
- Run a journey twice before trusting it: the first run of a build fills the caches and files the screens for the warm-up. It is the real engine, not his 120Hz display.
- More journeys: `fx` (the forex side, as `trade`), `firsts` (first openings only on the trading side, short: run it three times per setting and compare the middle values, single runs differ by a factor of two), `corners` (stills: the account button on each panel, the bottoms of the day tiles), `seedprep`, `year-finance` / `year-crypto` / `year-idx` / `year-fx` and `dump` (they make `public/warm-seed.json`, see "First launch"). `--prof` records which functions the script's time goes to (build with `--minify false` to get their names). With `--cold` the recording starts once the preparation is over. The hidden app asks macOS not to put it to sleep (App Nap stopped its timers twice, always the fourth run in a row). More flags: `--profile=<name>` (a data folder of its own, empty to begin with, kept between runs), `--cold` (the app is told the graphics cache is empty and prepares before its opening; the journey starts once that is over; with `--shots` a still of the preparation is taken).

The hidden app is given `--expose-gc` like the real shell.

- **What the numbers can and can't say** (learned 9 October 2026): the hidden engine makes 60 frames a second, so the gap list only shows a block longer than a frame, in steps of 17ms: it can't tell 20ms from 30. For milliseconds run with `--trace` (it slows everything by about half, so compare traced with traced). A step that follows a long rest is slowed by macOS itself (a hidden app in the background is put on the slow cores: the same chart opened in 92, 121, 243 and 434ms over four runs), so a single slow step after a rest proves nothing.
- **To measure with a really empty graphics cache**, as on the installed app's first launch: copy `node_modules/electron/dist/Electron.app` (`cp -Rc`), give the copy and its four helpers another `CFBundleIdentifier` (`PlistBuddy`), sign it again (`codesign --force --deep -s -`), and run `run.cjs` with that copy's `Contents/MacOS/Electron`. Its cache is `$(getconf DARWIN_USER_CACHE_DIR)/<the new id>.helper`: delete that folder before each run. A trace is several hundred MB: delete the output folders afterwards.
