# Export, Import, Undo, a copy a day

One area of Flow. What applies everywhere, and the list of the other areas, is in the project's `CLAUDE.md`.

- **Export** (all three sides; 4 October 2026, at his request):
  - In the Mac app the file goes straight into `~/Documents/misc/react app/Financial Tracker/exports`, in a folder per side, with no save box (`EXPORT_DIR`, `EXPORT_SIDES` and the `will-download` handler in `electron/main.cjs`, which picks the folder from how the file's name starts): `financial exports/rassam-pnl-export-DD-MM-YYYY.json`, `crypto exports/rassam-crypto-export-…`, `idx exports/rassam-idx-export-…` (his folder and file names), and `forex exports/rassam-fx-export-…` after them. **Every file's name begins with the account's first name** (11 October 2026, his example: "rassam-...-export-11-10-2026"; `userFilePre`: small letters and digits only, the account's id when nothing is left of the name). The shell finds the side after that name (`exportSide`), and a file named the old way, side first, still finds its folder. Files exported before that day keep their old names. **Exporting again never replaces a file** (11 October 2026: "it should have a (1) or (2) at the end so it doesnt replace the previous one but stack on top"; `freeName` in `electron/main.cjs`): the first of a day keeps the plain name, the next are `… (1).json`, `… (2).json`. Until then a second export on one day replaced the first. In a plain browser it is an ordinary download.
  - **A backup with nothing in it is neither written nor taken in** (`EMPTY_BACKUP`; all four sides; same day). He had pressed Reset account, exported the emptied account (a 164-byte file with no entry in it) and then found that importing it "restored" nothing: it emptied the app and said "Backup restored". Now Export on an account with nothing of his own says "Nothing of your own to export yet" and makes no file (test data is not his own), and Import of an empty backup says "That backup is empty, nothing was changed". The file's name had nothing to do with it: the import never reads the name.
  - When he reports entries gone or a backup that brings nothing back, **look at what is saved before anything else** (`tools/perf` journey `keys` on a copy of his Local Storage): that day everything was under `aside:` from his own Reset account, and "Restore my entries" in the sidebar was the way back. Never write to his data folder.
  - A backup holds only what he entered himself: generated test entries (`test: true`) are left out (`ownEntries`; test goals and test deposits too). Limits, the currency and the debts go along.
- **Import:** validated, with a 10-second undo. An income counted over several months keeps its `months` in a backup and through `migrateIncomes` (23 October 2026, see "One income over several months" in `notes/finance-day.md`); a build from before that day reads it as an ordinary income of its month.
  - **Import takes any Flow backup, on any side** (`backupSide`, `importSide`, `takeFinance`, `takeSide`, `onOther`; 11 October 2026: "import entries from any file (and from any user)"). Nothing in a backup says whose it was and the file's name is never read, so any account takes in any account's file under any name: that was already so. What changed: a file of another side than the one on screen is no longer refused. The side is read from what is in the file (`app` on a trading backup, `spending` / `incomes` on a finance one) and the backup goes there: a trading side that is not on screen has it written under its own key, cleaned as that side cleans it, and reads it when next opened; a finance backup handed to a trading side goes through the finance import. It says so ("That was a crypto backup: restored on the crypto side") and Undo puts back what that side had. Something that is no Flow backup still changes nothing. A side whose saved trades can't be read is never written over.
  - I read his sentence as that; he did not say which file had failed. If he meant something else (adding a file's entries to what is there instead of replacing, say), that is still to do.
  - Checked with the `plans` journey: from finance a crypto file, its undo, a stocks file, a file that is no backup, a finance file; from crypto a finance file, a forex file and a crypto file: each landed under its own key only, and the crypto side opened afterwards showed the trade.
- **Undo after a delete** (`offerUndo`, `undoHub`, `UndoNote`, `backInto`, `UNDO_MS`, `.undo-note`; 13 October 2026, from the critique he asked for; he chose "Safety net" first). Only Import had an Undo; a deleted trade took its review and pictures with it.
  - Whatever a bin removes can be put back for 10 seconds: a small solid note at the foot of the window, "Deleted kopi · Undo". One note at a time; the next delete takes its place. It is always there and only moved and faded (transitions).
  - Wired into: an expense and a no-spend mark, an income (row and chip), a goal, a debt, a plan's bin, a trade, a deposit or withdrawal. **Not**: an item inside an expense (that is an edit of the expense), an account (asked twice already).
  - `back` puts the entry into what is saved **at that moment**, at the place it had (`backInto`: never twice). A no-spend mark only goes back on a day still empty; an expense put back takes a mark off its day, as adding one does. A trade's pictures are still kept: they are only swept the next time that side opens.
  - A plan's tick (`planApi.log`) removes quietly (`remove(id, true)`): its plan became an expense, it was not thrown away.
  - An offer goes when its side leaves the screen (`TradeTracker`'s unmount, `onFinance` in the root) and at an import: no `back` outlives the entries it was made for. **A new bin calls `offerUndo(name, back)`.**
  - Checked with the `safety` journey: the note off at rest, "Deleted kopi" at full strength after the bin with the day saved empty, and after Undo the same entry with the same id. Not pressed: the other seven bins (the same two functions), the note running out by itself.
- **A copy a day** (`autoBackup`, `financeBackup`, `AUTO_KEY`, `AUTO_WAIT_MS`, `AUTO_LATEST_MS` in `App.jsx`; `keepBackup`, `AUTO_DIR`, `AUTO_KEEP`, `AUTO_NAME` in `electron/main.cjs`; same day, same choice). Export was by hand only.
  - The first time the Mac app is opened on a day, what the account entered is written into `exports/automatic backups`: one file per side that has entries, **named and built as Export's**, so any of them can be handed to Import. A day's file is never written twice (it is how things stood when the app was first opened that day), and the last 7 days of each account's each side are kept. Which account had its copy on which day is noted under `flow-auto`, beside `flow-users`: nobody's data, in no backup.
  - Left out, as in an export: test entries, a side with nothing of his own. **Left out, unlike an export: the pictures on trades** (reading them all at a launch could lag); a trade goes on naming its pictures, which stay in the app's own store. So a copy brings back entries, not a picture that was swept meanwhile.
  - **The shell only ever removes a file in that folder whose whole name fits `AUTO_NAME`**; an export he made himself is in another folder and is never touched. It is a write to a file, not a request: the rule about the two internet exceptions is untouched.
  - It runs in an idle gap with 10ms of room, 8s after the entries are read, 20s later at the latest, and not while something is on its way in or out. **An idle callback's own `timeout` is no use for that** (so `warmWhenIdle` with a timeout is not either): on the panels before an app something always floats, a callback comes every frame with too little room, and asking again starts the timeout afresh. It never ran there until it had a deadline of its own.
