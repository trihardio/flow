# Flow

Flow is a private, personal macOS finance app for Rassam: a PnL-calendar spending tracker in IDR, with optional MYR. It is for personal use only, so trademark and branding concerns don't apply.

It was called Trace until 2 October 2026. Everything is named flow now, at his request: the project folder, the package `name` and `appId` (`com.rassam.flow`), `window.flowAI` / `window.flowFX`, `models/flow-ai.gguf`, the installer, and the data folder `~/Library/Application Support/flow`.
- One name must stay: the page address `app://trace`. What the page has saved is filed under that address inside the data folder, so changing it would hide all his data.
- The data folder was `trace`. `electron/main.cjs` moves an old `trace` folder across on launch if it still finds one (and goes on using it if the move fails); don't remove that. A copy from before the move is in `~/Library/Application Support/flow-backup-2026-10-02`.
- The save points were given the new `window.flowAI` / `window.flowFX` names too, so loading one still gets the AI helper and the live rates.

A second side is built on the same lines: a trading PnL tracker with two sections, crypto and Indonesian stocks (Rassam calls the second the IDX/IHSG panel). The way in is the selections panel, then a trading selection with the Bitcoin coin and the IDX globe. Both open the same tracker (`TradeTracker`), the coin in USDT and the globe in rupiah.

## Project layout
- The whole app lives in one file: `src/App.jsx` (~645 KB, React). Keep it as a single file unless the user asks to split it.
- `src/main.jsx` mounts it and loads `src/fonts.css`. Vite is the dev server and bundler (`npm run dev`, `npm run build`).
- `src/fonts.css` + `src/fonts/`: Inter, Material Symbols Outlined, Ballet, Mrs Saint Delafield and Press Start 2P, stored locally. Never load fonts or anything else from the internet.
- `electron/` is the Mac app shell:
  - `main.cjs`: window, serves `dist/` from `app://trace`, blocks every internet request the page could make, runs and caches the AI helper.
    - Two deliberate exceptions, both asked for by Rassam, both made by this process in a session of its own (the page itself still can't reach anything, and everything works offline with the last data). Add no other request.
      - `fetchRates`: the latest USDT → IDR / MYR rate (CoinGecko, then open.er-api.com as a fallback), when the crypto side asks.
      - `fetchQuote(market, symbol)`: the latest price of the coin or stock typed in a calculator (2 October 2026: "fetch data from the internet in real time"). Sources per market in `QUOTE_SOURCES`, best first: crypto is Bybit, Binance futures, Gate.io futures, Binance's public spot mirror, TradingView; stocks are TradingView, then Yahoo. A source that can't be reached rests ten minutes; the one that last knew a name is asked first.
      - His internet provider blocks Bybit, Binance, Coinbase, OKX and most big exchanges (they land on internetpositif.id), so on his line crypto prices come from Gate.io (the USDT perpetual, live, about 0.1s). They stay first in the list for when he is on another line. Don't work around the block.
      - Before a source is first asked, `checkHost` looks at its certificate outside the browser engine. Without that, each try at a blocked exchange printed `handshake failed … net_error -200` in the terminal (he asked what it was). Keep the check.
      - Stock prices run about 10 minutes behind the exchange (TradingView's free IDX feed). Nothing free and without a login is fresher: Stockbit needs his account, idx.co.id refuses programs, Yahoo rate-limits. He has been told.
  - `preload.cjs`: exposes `window.flowAI.pick(kind, text, labels)`, `window.flowFX.rates()` and `window.flowFX.quote(market, symbol)`.
  - `ai.mjs` + `ai-classify.mjs`: the on-device model process and the code that turns its output into a label.
  - `ai-head.json` (11 MB): what the classifier learned. Generated by `npm run train-ai`; do not edit by hand.
- `models/flow-ai.gguf` (329 MB, EmbeddingGemma 300M Q8) is the on-device model; `build/icon.png` is the app icon.
- `tools/ai/` trains the classifier (not shipped in the app):
  - `cats.txt`, `cats2.txt`, `goals.txt`: hand-written labelled notes. `distilled.txt`: 5,182 more, written and labelled by a 2.5 GB teacher model (`distill.mjs`; the teacher is not kept in the project).
  - `tests.json`: held-out notes for scoring. `train.mjs` prints the held-out score, then writes `ai-head.json`.
  - To teach it something new: add notes to `cats.txt` or `goals.txt`, run `npm run train-ai`, then rebuild the app.
- `tools/perf/` hunts lag (not shipped in the app): it drives a build through a journey in the project's own Electron with no window on screen, on a copy of his entries, and reports per step how long the page was busy in one go, how long the graphics process was stuck, and how many graphics programs had to be built. Each step is done twice, because the lag he notices is the first time a thing is opened after a launch.
  - `npx vite build --outDir "$TMPDIR/flow-perf/dist"`, then `env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron tools/perf/run.cjs finance --trace` (also `trade`, `stocks`, `launch`, and `cards`: the finance month scrolled down card by card, then Money flow folded and opened twice), then `node tools/perf/report.cjs finance` (`--programs` lists the graphics programs).

  - From a VS Code terminal, Electron needs `ELECTRON_RUN_AS_NODE` unset; the `app` script does that.

## Architecture notes
- **Storage:** the `store` adapter uses `window.storage` when present (the Claude sandbox), otherwise `localStorage`.
  - Keys: `pnl-calendar-idr` holds the data; `pnl-test-config` holds the test-data settings.
  - Data from the old Claude-hosted version does not carry over automatically. The user must Export there and Import here.
  - The Mac app keeps its own data (origin `app://trace`), separate from the browser version: Export there, Import in the app.
- **Saving:** writes go through a persist chain that merges into the `latestData` ref.
- **Loading:** `migrateSpending` and `migrateIncomes` sanitise what is loaded. `MAX_AMOUNT = 1e13`.
- **Export** (all three sides; 4 October 2026, at his request):
  - In the Mac app the file goes straight into `~/Documents/misc/react app/Financial Tracker/exports`, in a folder per side, with no save box (`EXPORT_DIR`, `EXPORT_SIDES` and the `will-download` handler in `electron/main.cjs`, which picks the folder from how the file's name starts): `financial exports/pnl-export-DD-MM-YYYY.json`, `crypto exports/crypto-export-…`, `idx exports/idx-export-…` (his folder and file names). One file per side per day: exporting again the same day replaces that day's file. In a plain browser it is an ordinary download.
  - A backup holds only what he entered himself: generated test entries (`test: true`) are left out (`ownEntries`; test goals and test deposits too). Limits, the currency and the debts go along.
- **Import:** validated, with a 10-second undo.
- **AI helpers** (auto-categorise, goal icons) run only in the Mac app: `AI_OK = !!window.flowAI`. In a plain browser the keyword rules work alone.
  - They are a fallback for names the keyword rules (`CAT_RULES`, `GOAL_ICON_RULES`) can't place.
  - Fully offline: a small embedding model in a separate process, loaded on first use and closed after five idle minutes (the Mac has 8 GB RAM; the helper uses about 110 MB).
  - How it decides: the model turns the note into a vector; a linear classifier plus a vote of the 5 most similar known notes picks the label.
  - Answers are remembered in `ai-cache.json` in the app's data folder; the cache empties itself whenever `ai-head.json` changes.
  - Held-out score (notes the keyword rules miss, not seen in training): expenses 197/207 (95%), goal icons 38/40 (95%). The 2.5 GB Gemma 3 4B it replaced scored 188/207 and 38/40 on the same notes.
  - Its weak spot is a rare single word that is in none of the lists; the fix is to add that word to `cats.txt` and retrain.
  - Dead ends, don't retry: zero-shot embeddings without training (65%), 1–1.5B chat models (53–76%), `getLlama({ gpu: false })` (no CPU-only binary on Apple Silicon; it tries to compile from source and bloats `node_modules`).
- **Test tools:** `SHOW_TEST_TOOLS` near the top of the file hides the test-data buttons for release.
- **Opening screen ("open app panel"):**
  - Logo and a pixel-font "FLOW" (`APP_WORD`; one falling piece per letter) on a grey centre gradient, about 1.5s (`OPEN_HOLD_MS`; 1.7s felt a bit long in the still middle).
  - The wordmark is Press Start 2P at 48px (an 8x8 grid font, so one font pixel = 6px): pure white letters, letter-spacing 6px (one extra font pixel, so no shadow touches the next letter), over a hard shadow offset by one font pixel. The shadow carries a slightly darkened pastel **green** gradient that steps once per pixel row. Keep the size a multiple of 8px so it stays on that grid.
  - Each letter is two stacked spans (`opw-sh` shadow under `opw-fg` text) so the shadow can be gradient-filled; `text-shadow` can't do that.
  - Then the outro: the logo drops off the bottom first, each letter follows at its own moment, speed, drift and spin (either direction). Nothing fades except the backdrop (`.open-panel-bg`): it starts 0.1s after the fall (`OPEN_FADE_DELAY_MS`), takes 0.62s (`OPEN_FADE_MS`, ease-in-out) and is gone just before the first piece leaves the screen. Rassam found 0.45s too fast; keep it unhurried but finished before the pieces exit.
    - The fall is rolled afresh for every play in `openFall` and handed to CSS as `--fd/--ft/--fy/--fx/--fr`; the motion is one transform keyframe (`openFall`) on a slow-to-fast speed ramp (`OPEN_FALL_EASE`, a cubic ease-in in CSS terms). No per-frame JS.
    - Rassam calls this ramp "ease out" (Premiere Pro's term for easing out of a keyframe): slow, then moderately fast, fastest at the end. Never read it as CSS `ease-out`.
    - The wallets are mounted `OPEN_PREP_MS` before the outro (`walletsReady`), hidden behind the still splash. Mounting them on the outro's first frame made the fall stutter.
  - At app start the logo and wordmark are held back (`.open-panel.wait`: in place at 1% opacity, so already drawn) until the fonts are loaded and unpacked and the logo is decoded (`warmFonts`, `openGo`; `OPEN_READY_MAX_MS` at the latest). That is about a tenth of a second, while the window is still opening. Everything after is timed from that moment, so the splash is as long as it was. Before, the 55ms unpacking of the icon font and a late pixel font could land in the middle of the logo coming in (he saw the intro lag "sometimes").
  - While the splash stands still (from `OPEN_WARM_AT_MS` to `OPEN_WARM_CLEAR_MS` before the outro) the **warm-up** runs under it; see below. If its last frame is late, the outro waits for it, `OPEN_WARM_LATE_MS` at most.
  - State: `openPanel` ("in" → "out" → "done"), plus `openRun`, which counts replays.
  - The footer logo (`goHome`) replays it: the splash fades in over the app (`OPEN_COVER_MS`), then `resetToWallets` swaps the app for the selections panel underneath.
- **Warm-up** (`warm*`, near the top of `App.jsx`; 3 October 2026): Rassam's complaint was that everything lags the first time it is opened after a launch (the wallets, a card scrolled to, a chart) and never the second time.
  - What a first showing pays for: text shaped in each font, weight and size; the system asked for a font for the characters Inter lacks (▾ ✕ ▮ ▬ → ← ⇄ ↔ ≈ ★: 30–50ms the first time); pictures decoded; and a small graphics program built for each new kind of paint, blur and blend (a burst of 25–40 of those froze a few frames). None of it can be asked for ahead of time except by drawing the thing.
  - So each screen is **filed** a moment after it settles (`useWarmScreen(key)`, in both `PnlCalendar` and `TradeTracker`): its markup goes into IndexedDB `flow-warm` (apart from his data, never in a backup), in idle gaps (`warmWhenIdle`), again at 7s and 25s if he is still there. Of a pop-up (`…+chart`, `+recap`, `+cat`, `+calc`) only the pop-up is filed. The 3D coin and the stage's backdrop are left out (`data-nowarm`).
  - At the next launch `warmReplay` puts each filed screen back for two frames (plus one per extra window-height, `WARM_MAX_SLICES`) in `.warm-host`: `inert`, `opacity: 0.004`, animations off, the hidden cards shown. The second frame repaints every second element (`.touch`), because redrawing part of a tile has programs of its own. Wallets and trading selection first, then panels, then pop-ups, most recently used first; about a dozen and a half fit. Nothing of it runs once the app is in use (an idle-time version was tried and dropped: it could land just as he clicked).
  - Stills taken during it differ from stills without it by nothing: at 0.004 it rounds to no change.
  - It never touches the real panels or their state. A screen he has never opened is not warmed; a new pop-up or panel gets warmed by giving it a key in the `useWarmScreen` call.
  - Measured in the off-screen engine (first opening after a launch, before → after): finance month 77 → 40ms busy (second opening 25), chart 55 → 21, wrapped 27 → 16, crypto calculator 83 → 18, crypto chart 35 → 11; graphics programs built after the start 106 → about 40 (finance), 70 → about 30 (trading). What is left is the script's own first run.
- **Selections panel** (between the opening screen and the wallets): a carousel of two on the wallets' own stage (`.launch-wrap.pick`), built to look like the wallets panel: the current-year wallet and a 3D Bitcoin coin. The one in focus is in the middle; the other is tucked to the side (wallet left, coin right) at the side-wallet size and dimness, plus a touch of blur. No labels.
  - State: `choice` (`null` = choosing, `"wallet"` = wallets panel, `"trade"` = on the way into the trading panel) and `pickFocus` (`"wallet"` or `"coin"`, which one is in the middle; adds `.pick-coin`). `resetToWallets` sets them back to `null` / `"wallet"`.
  - A press on the tucked one, or the scroll wheel, brings it into focus (`focusPick`). A press on the one in focus goes in. Only the one in focus tilts under the pointer.
  - The blur on the tucked one is switched, never animated: `filter` has a 0s transition with a 0.26s delay on the way out and none on the way back.
    - The wallet, the coin and the globe all carry `filter: blur(0px)` at rest, so tucking one away only changes the blur's strength. Gaining or losing a filter makes every layer under it be drawn again; on the wallet that was 25 graphics programs built at once, the few frozen frames of the first wallet ⇄ coin switch after a launch. Never give these a state without a filter. Stills before and after are the same to within 2/255.
  - The wallet is the real wallet unit of the current year (`HOME_WALLET`: the entry of `WALLETS` with `year: 0`), so its cards and expiry are whatever the wallets panel gives that year. Pressing it in focus, cards included, opens the wallets panel around it; the wallets panel itself is unchanged. Esc steps back out: pulled-out card → wallets → selections panel. The hidden arrow in the top-left corner (`.pick-back`, wallets panel only) does the same step; it is invisible until the pointer is in that corner.
  - The coin (`BtcCoin`, `COIN_*`) is deliberately plain, after Rassam's reference (he found beads, circuit traces and a ridged edge "way too detailed"): a wide rim, one thin ring, a big pale symbol standing on darker side walls, and a thick smooth edge. Keep the gold. The edge is `COIN_SIDES` flat strips in a `preserve-3d` box, so the thickness is real geometry; each strip's two shades are worked out once for the resting pose (`COIN_REST`). The faces are SVG: whatever is raised is drawn as a height map and lit (`#cnEmboss`), then laid over the metal as highlight and shadow. No blend modes.
    - Three nested boxes: `.coin-tilt` (pointer tilt, written from JS by `stepCoin`, which also turns the lustre `.cn-lustre`), `.coin-float` (idle float, only while the coin is in focus and not under the pointer), `.coin-3d` (resting pose; flips when pressed).
    - Keep `opacity`, `filter`, `overflow` and blend modes off those three boxes: any of them flattens the 3D. Fades, moves and the blur go on `.coin-unit`.
    - On the wallets panel the coin is `visibility: hidden` once it has faded, so its ~100 layers cost nothing there.
    - Against a hitch the first time the coin comes into focus (he noticed it on first launch): everything the coin is painted on has `will-change: transform`, so it is painted at full size from the start instead of small and then again big; and `.coin-unit` always carries `filter: blur(0px)`, so gaining focus only changes the blur's strength rather than rebuilding how the 3D coin is drawn mid-move.
    - When the wallet is chosen the coin must be gone before the next year's wallet arrives in its place (0.18s fade); coming back, it waits 0.12s for that wallet to leave. Otherwise the two show through each other.
  - Pressing the coin in focus (`openMarkets`) opens the **trading selection** (`choice === "markets"`, `.launch-wrap.markets`): the same carousel of two, now the coin (crypto) and the IDX globe (Indonesian stocks), with `marketFocus` (`"crypto"` / `"idx"`) saying which is in the middle. The wallet slips away to the left and the globe comes in tucked on the right. Esc and the hidden top-left arrow (`.pick-back`) go back to the selections panel with the coin in focus.
  - The one in focus, pressed, goes in (`enterTrade(kind)`, which sets `tradeKind` and `.trade-crypto` / `.trade-idx`); the other fades where it is. Then the stage fades and that trading panel is underneath (`view === "trade"`). Either way that is `TradeTracker`, told which market. Its crocodile goes home like the finance footer's.
    - Crypto: a coin flip on the spot (`coinFlip`: twice end over end while turning once round, with a small hop from `coinHop`; it stays anchored in the middle), with a directional motion blur along the tumble while it is fastest, then the fade after `TRADE_FLIP_MS`. He rejected an even (Gaussian) blur: it must smear up and down like a real motion blur. CSS can only blur evenly, so three plain boxes wrap the coin (`.coin-smear`): the middle one blurs (`coinBlur`), the outer one squeezes it sideways to a quarter and the inner one stretches it back, which leaves the blur four times weaker sideways. An SVG blur filter stepped through keyframes was tried and dropped.
    - IDX: the globe spins once round its axis (`IDX_SPIN_MS`), lifts and shrinks a little (`.idx-lift`), and the wordmark "IDX / Indonesia Stock Exchange / Bursa Efek Indonesia" comes up under it, laid out as in the logo. The wordmark shows only then. The fade starts after `IDX_REVEAL_MS`.
  - The IDX globe (`IdxGlobe`, `.idx-unit`): `IDX_BANDS` (the white bands) and `IDX_WORD` (the wordmark) are vector outlines traced from Rassam's picture of the logo, in a 400-unit square that the globe fills; don't redraw them by hand. The red disc, a soft gloss and a ground shadow are CSS.
    - It is a real 3D ball, not a rotated picture (he rejected the flat 2D rotation: "it doesn't feel like a globe"). A small WebGL program (`idxGlobeGL`) draws only the white bands on a ball turned about an axis leaning `IDX_TILT` degrees, so they bunch up at the rim and come round from the back like the earth. At a turn of 0 it is exactly the flat logo, which is why the flat SVG can stand in until WebGL is set up and for good if WebGL is missing. WebGL is set up 0.9s after the trading selection opens (the globe is tucked, small and blurred then, so the swap can't be seen), never earlier: set up just after the opening it collided with the first presses on the selections panel. The context is handed back when the app is entered.
    - One loop (`stepGlobe`, `globeAnim`) works out the turn and draws: the pointer's pull (it follows the pointer left and right), a slow sway to and fro while it floats idle, and the full spin when pressed. It stops when nothing is moving. The idle bob is CSS (`.idx-float`), paused under the pointer and while tucked away.
- **Trading tracker** (`TradeTracker`, a module-level component above `PnlCalendar`; `market` is `"crypto"` or `"idx"`): Rassam asked for everything to be the same as the finance side (yearly panel, monthly panel, all the GUIs) but crypto-PnL styled, after Bybit, Binance and Axiom, and then for the IDX/IHSG panel to be "the same thing" as the crypto one.
  - It is a component of its own on purpose: it reuses the finance side's styles, classes and animations (`S`, `.ycell`, `.cell`, `.flow-card`, the chart classes, the title flicker, the wrapped), but none of its state, so work on it can't break the finance panels. When a finance GUI changes, mirror the change here.
  - `MARKETS` lists everything that differs between the two: storage keys, the currency trades are kept in and its decimals, whether a trade has a side, the words (pair / stock, Coins / Stocks), the grey text after a name, the test data. Add a difference there, not as an `if` on the market name.
  - Data: `trades`, day key → `[{ id, pnl, pair, side }]`. `pnl` is the realised PnL, signed: US dollars with cents for crypto, whole rupiah for stocks. Exactly 0 is a break-even trade (the crypto journal's Breakeven): it counts as a trade, neither won nor lost (`tally`), with a grey dot and "1BE" on its day. `side` is `"long"` or `"short"` (stocks are always long, and show no side). Crypto is stored under `pnl-crypto-usd`, stocks under `pnl-idx-idr`, never mixed with each other or with `pnl-calendar-idr`. `migrateTrades` sanitises what is loaded or imported. Each side has its own Export / Import (`crypto-pnl-backup-…`, `idx-pnl-backup-…`) and refuses the other's file and the finance one.
  - What maps to what: gross profit ↔ income, gross loss ↔ spending, net PnL ↔ what's left. The bar is profit against loss. A day cell shows the day's net PnL, wins and losses (`2W · 1L`) and one dot per trade; a month box shows net PnL, trades and win rate.
  - Day panel, stocks: a Profit row (green +) and a Loss row (red −), each an amount and a name, like Income and Expenses. The sign comes from the row, so amounts are typed without one, the finance way (1.250.000, and the grey `.000` to accept with Enter); nothing is written after the ticker.
  - Day panel, crypto: the **trading journal** (`TradeJournal`, `TradeSheet`, `MARKETS.crypto.journal`; 4 October 2026, after his picture of a Notion trade page). It replaced the Profit / Loss rows on the crypto side only.
    - A trade is a sheet of properties: Win / Breakeven / Loss and the $ box on top (he asked for both at the very top), then Coin (a grey `USDT.P` written after it, `PairBox`; `coinOf` groups pairs by coin, BTCUSDT and BTC/USDT → BTC), Position (long / short), Time frame (`TF_LIST`), Duration, Full TP % (his replacement for the picture's Range %: how far the full TP is from the entry), Risk %, Leverage, R / Factor, Pre notes, and Description (the picture's Post notes, in a bigger box than the rest, at his request).
    - He had Type, Limit, Confidence, Macro EW, Fib match macro and Day taken out; don't bring them back.
    - Colour, as he asked: the picture's symbols were "too boring and bland", so each icon has its own muted tint, and of the text only the result with its amount, the position, the time frame, the full TP and the R are coloured. Nothing bright or saturated ("don't show off, no colour vomit").

## Performance rules (learned the hard way)
- Define components at module level, or call them as plain functions. Never define them inside another component's render: that causes remounts and focus loss.
- No React state inside requestAnimationFrame loops. Write styles straight to DOM refs (see `writeTilt`, `placeBg`).
- Animate only `transform` and `opacity`. Never animate `filter`, `width` or blur.
- A `transition` or `color` in an inline style (the `S` table) silently beats the class's. That is how the day tiles' and month boxes' eased lift, the fold arrows' hover and the month label's hover were written and never played. Keep what a class hovers or eases out of the inline style.
- A gradient can't be transitioned; a registered number can. The tiles' sheen is worked out from `--lit` (`@property`, 0 → 1 under the pointer), which at 0 and 1 gives exactly the two gradients that used to be switched.
- Entrance animations use `animation-fill-mode: backwards` with an explicit end state, never `forwards` or `both`.
  - A held animation creates a backdrop root that breaks `backdrop-filter` blur on liquid-glass elements.
- Avoid nested or invisible `backdrop-filter`s.
- **Anything that changes the page's height must not redraw the page** (4 October 2026: he reported lag whenever Money flow was folded or opened; the graphics process was stuck 7–21ms on most frames of the fold, measured with the `cards` journey, and not once after these):
  - The backdrop is one picture of a fixed height (`PAGE_BG`, an SVG as a single `background` layer on `body`). With several background layers, or one sized from the box, the engine redraws the whole backdrop whenever the box's height changes. It matches the old six CSS gradients to within 1/255 (compared with the content hidden). Never go back to several layers or a height in %.
  - Every card (`.flow-card`) and what folds inside it (`.fold-in`) keeps `will-change: transform`: a surface of its own, so a fold only moves the cards below and cuts its own content off, without drawing either again.
  - A card's seen / open / replay state lives in the card (`FoldCard`), and a part's in `Reveal`, never in `PnlCalendar`: setting it there worked the whole panel out again (17ms) as each card came into view and on every press of an arrow.
- Chart tooltips are HTML `GlassTip` elements laid over the SVG, positioned in viewBox percentages.
- The Mac's display runs at 120Hz, so a frame has about 8ms. Measure in the real Electron app, not the browser.
- Fonts are loaded and unpacked before the opening screen's pieces come in (`warmFonts`), and two hidden spans at the top of the page get the rest ready in the very first layout: one `.msym` icon (the 4MB icon font takes about 55ms to unpack), and the characters Inter lacks, which the system supplies from its own fonts (30–50ms the first time it is asked; it used to land in the first month view and the first chart).
- First-time lag is the warm-up's job (see Architecture notes). When something still lags only the first time, measure it with `tools/perf` before guessing: the page being busy, the graphics process being stuck and graphics programs being built are three different causes with three different cures.
- An element that gains or loses a `filter` (or anything else that gives it a surface of its own) has every layer under it drawn again. Give it the filter for good, at strength 0 (`blur(0px)`), and change only the strength.
- Work that can wait (filing a screen, saving something big) goes into an idle gap with room for it (`warmWhenIdle`), in pieces of a few ms: a 17ms piece once landed on the very frame of a click.
- `electron/main.cjs`: the `app` scheme has `codeCache: true` (compiled script kept between launches), and background throttling is left on so a hidden window costs nothing.
- The very first launch on a fresh profile stutters while the graphics pipelines are built and cached (`GraphiteDawnCache` in the app's data folder). Later launches reuse them: a program then takes about a millisecond to set up instead of a hundred or more. The same goes for the first launch after a screen is first filed for the warm-up.
  - The engine's own switch for this (`enable-skia-graphite-precompilation`) was tried: it builds a fixed list that doesn't cover what this app draws, and slowly. Don't retry.

## Style
- iOS 26-style "liquid glass" UI on a dark grey gradient, with smooth, premium animations.
- Yearly panel header: after the wallet → year intro, the year digits flicker from the normal font into the pixel font. They wait `YEAR_FLICK_DELAY_MS` (0.4s) after the panel appears; starting at once felt too fast.
- Year arrows (`.ynav-btn`): at the first or last year the arrow fades to its greyed-out state over 0.32s, and back. Rassam noticed it cutting straight to grey.
- Every ✕ (`.x-btn`), the calculators' gear and the × on an income chip (`.chip-x`) light up under the pointer.
- Footer buttons (both sides): Export, Import, Add test data and Clear test data are symbols without a border (`.bk-btn.ico`: download, upload, science, delete_sweep), with the usual highlight under the pointer and their name as the tooltip. Undo and Reset stay words.
- A highlighted box must be whole: the same round corners on every side. What folds away (cards, lists, the wrapped's detail) sits in `S.fold`, which cuts off top and bottom only (`overflow-y: clip`, `overflow-x: visible`). A plain `overflow: hidden` there sliced whatever reached a few px past the sides and left it square on one side: the "Last 7 D" tab, the rows of the win / loss ring. Rassam sent pictures of both that and the Income label of the money-flow chart, whose highlight is now only as wide as its text (as wide as its slot, it ran out past the card's edge).
- Month panel header: the title is the name of the month being viewed ("October"), in the pixel font (Press Start 2P, 24px); clicking it opens the month's wrapped. The ‹ › month arrows are invisible until the pointer is on the month switcher (`.month-nav`).
- The grey gradient behind the yearly and monthly panels is the page's own background (`body`), so it scrolls with the UI: lighter graphite at the top, deepening on the way down, with soft glows placed in px along the page (`PAGE_BG`, see the performance rules). Rassam does not want a still, fixed backdrop.
  - It needs `!important`: `index.html` and the boot code give `body` a plain inline colour, which silently covered the old fixed `body::before` gradient.
- Charts:
  - Grey for no-data spans, with a hard colour switch at each data point.
  - Lines start at the y-axis, at 90% of their first point's value (`CHART_LEAD`), so they come in with a slight rise. From zero it was a wall from the corner up to January, which he found weird.
  - The x-axis stays one unbroken white line: a level that falls on it draws no grid line, and the dashed zero line is drawn only when zero is above the axis. Both used to be drawn over it (he noticed the axis was "not fully white").
  - Weekly line: green below 75% of the daily limit, yellow up to the limit, red above it.
  - Income bars (chart pop-up): each bar has a soft top-to-bottom gradient, light green to a slightly deeper green (`incBarG`), never dark. The biggest income of the period uses the lighter `incBarTopG`.
